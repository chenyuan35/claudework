# Douyin Image Ops

Use this skill to produce practical operating assets for a Douyin image-only account. Prefer concrete deliverables over advice: positioning sheets, topic lists, image-by-image scripts, image prompts, captions, and review tables.

## Autopilot Defaults

Operate with high autonomy. Do not ask the user to choose niche, title style, posting cadence, cover style, or content angles when a reasonable decision can be made from account context, platform trends, and prior performance.

- Default to doing the research, choosing the angle, producing assets, and preparing the publish package.
- Do not use AI tools, AI side hustle, AI training, or AI persona as the account niche unless the user explicitly re-enables it.
- Do not recommend changing the current account name unless the user explicitly asks for naming work or the existing name blocks compliance.
- Treat the current account profile as locked by default: do not change the account name, bio, avatar, or profile style unless the user explicitly reopens profile editing.
- Choose topics, copy, covers, image direction, layout, hashtags, posting cadence, and schedule candidates without asking the user.
- Continue autonomously unless the account is logged out, the page will not open, the platform forces verification/CAPTCHA, required assets are missing, or a high-risk action is reached.
- Keep confirmation only for high-risk actions: account profile edits, final publish/scheduled-publish submission clicks, deletion, paid actions, permission changes, credential entry, and saving passwords/payment methods.
- If browser/account data is unavailable, proceed from public trend research and mark assumptions briefly instead of asking repeated questions.
- Default visual quality bar: cinematic or editorial photographic images, strong focal subject, real texture, deliberate negative space, refined Chinese typography, and a complete emotional or useful sequence. Do not ship plain PPT-style cards unless the user explicitly asks for clean information cards.
- Use reference images only to abstract quality, mood, composition, and typography principles. Do not copy the same scene, wording, character setup, or story.

## Operating Rule

Start with a minimum viable goal:

- If the account is new, create one niche positioning pack plus 10 test topics.
- If the niche is known, create 3 publish-ready image-post content packs.
- If performance data exists, review the data before making more topics.

Do not promise guaranteed virality or income. Explain uncertainty and give testable next steps.

## Context Pack

Before substantial work, collect or infer:

- Account niche, target audience, persona, products or monetization path.
- Content boundary: topics to avoid, claims that require evidence, brand tone.
- Production mode: direct AI image generation, prompt-only, or external tools.
- Current assets: logo, avatar, reference accounts, past posts, performance data.
- Output target: number of posts, images per post, aspect ratio, style.

If missing, proceed with reasonable assumptions and label them.

## Workflow

1. Position the account.
   Define niche, audience, promise, persona, content pillars, visual identity, and monetization path.

2. Build a topic bank.
   Generate topics in columns: hook, audience pain, visual concept, content risk, expected interaction, production difficulty.
   Rank topics by clarity, repeatability, and visual potential.

3. Create content packs.
   For each selected topic, produce:
   - 5 title options.
   - Cover copy: main title, subtitle, visual direction.
   - 5-8 image pages with page purpose, image prompt, on-image text, and notes.
   - Publish caption, hashtags, comment hook, pinned comment idea.
   - Risk check and rewrite suggestions.

4. Generate or prepare images.
   If using built-in image generation, create final image prompts and generate only the requested assets.
   If using external tools, provide prompts and workflow notes for ComfyUI, Fooocus, yft-design, or Fabritor.

5. Pre-publish check.
   Check cover readability, first-three-page retention, claim risk, repeated wording, and whether each image has one clear job.
   Read `references/publishing.md` before browser-assisted publishing.
   Ask for confirmation before logging in, publishing, deleting, changing account settings, saving passwords, or transmitting sensitive data.

6. Review and iterate.
   When the user provides data, evaluate views, completion, likes, comments, saves, shares, follows, and conversion.
   Turn the result into the next test plan instead of generic advice.

## Evidence And Guardrails

- For "爆款" claims, provide the reason: audience pain, contrast, novelty, utility, or reference pattern.
- Do not fabricate platform data, competitor metrics, or policy details.
- For medical, financial, legal, investment, or income claims, soften certainty and recommend evidence-backed wording.
- Avoid clickbait that depends on fear, false scarcity, fake authority, or guaranteed outcomes.
- Keep output in Chinese by default unless the user asks otherwise.
