### 步骤 5：分节生成执行机制（2026-07-24 用户纠正，替代原"段落级字数预算分配"和"一次写足规则"）

> **🔴 核心原则：永不覆盖已写正文。每节独立生成并追加。禁止进入"重写—统计—再重写—仍不够"的循环。**

#### 5.1 字数目标
- **汉字 ≥ 3,000**（用 `len(re.findall(r'[一-鿿豈-﫿]', text))` 验证，禁止用 `len(str)`/Token 计数字数）
- 全文字符数（content.length）作为参考值，不以此为目标

#### 5.2 分节预算（动笔前确定）

```
[开头·引出书]           → 目标 ~500 汉字
[触动点1]               → 目标 ~1,000 汉字
[触动点2]               → 目标 ~900 汉字
[触动点3]               → 目标 ~300 汉字
[结尾·收束]             → 目标 ~200 汉字
合计                     → 目标 ~2,900 汉字（允许追加）
```

#### 5.3 执行流程（严格按此顺序）

**① 生成第1节（开头）**
- 写第一版 → 记汉字数 → 比较预算
- 不足 → 仅向本节追加内容，**不覆盖已写正文**
- 达标 → 追加到全文变量，写下一节

**② 生成第2节（触动点1）** — 同上：写→计→不足追加本节→达标追加到全文
**③ 生成第3节（触动点2）** — 同上
**④ 生成第4节（触动点3）** — 同上
**⑤ 生成第5节（结尾）** — 同上

**⑥ 全文汉字统计**
- 只统计汉字：`len(re.findall(r'[一-鿿豈-﫿]', full_text))`
- ≥ 3,000 → 跳到⑦
- < 3,000 → 仅向**指定章节**追加内容（如"向触动点2追加300汉字"），禁止重写已有正文

**⑦ 统一拆段**
- 全文汉字达标后，才做段落拆分
- 把每段拆到 ≤ 60 字，拆段**不得删改任何内容**
- 只加段间空行，不改字词句

#### 5.4 回滚规则（防死循环）

- **每次修改前**：用 `cp article_content.md article_content.bak.N` 备份当前版本到工作区
- **每次修改后**：重新统计汉字数
- **连续2次修改后汉字数下降** → 立即停止，恢复上一个bak版本，不再修改
- 恢复后，汉字数≤上一版 → 宣布本文无法达标签，熔断，通知用户

#### 5.5 版本备份规范

- 备份文件命名：`jianshu_draft_bak_N.txt`（N为递增序号）
- 执行完成后保留最终版，删除所有bak文件
- 始终能用 `ls -la jianshu_draft_bak_*.txt` 查看备份链

#### 5.6 禁止行为清单

- ❌ 禁止覆盖全文变量（每次覆盖 = 丢弃进度）
- ❌ 禁止先写框架后加厚（每节第一版就要接近预算）
- ❌ 禁止反复重写同一节（差额只在当节追加）
- ❌ 禁止未达汉字数就拆段（拆段改段落不改文字）
- ❌ 禁止 Python `len()` 或 Token 代替汉字计数
- ❌ 禁止"重写—统计—再重写"循环（见 5.4 回滚规则熔断）

### 内容策略

**一句话定位**：一个普通人在简书记录他读过的每一本书。

不冒充专家，不写书评装深刻。就是**读完一本，写写这本书讲了什么、我有什么感觉、哪个点让我想了半天**。

**选题标准**（更新版 v1.11+）：
- 每天选一本读过的书，或者正在读的
- 类型不设限：工具书/小说/传记/散文/技术书
- **优先选有"认知反差"的书**——大众固有印象 vs 书中真实内容（围城/格林童话已验证高赞）
- 其次选有强个人共鸣点的——读到心里去了（被讨厌的勇气 23赞）
- 不为了读书而读书，写真实感受
- **避雷**：太冷门/太小众的书做了也没人知道，先选有认知基础的

**简书风格铁律**：
- ❌ 不写"本书概要""作者简介"等百度百科式开头
- ❌ 不写推荐语（"强烈推荐""必读"）
- ❌ 不写思维导图式结构
- ✅ **连续两篇文章禁止用相同或高度相似的开头骨架**（见 §R.2.1 结构分析规则）
- ✅ 挑最打动自己的 1-3 个点展开

### §R.2.1 开头多样化规则（v1.24 重写）

**2026-07-10 发现的问题**：从《围城》到《小王子》到《平凡的世界》，连续三篇开头全是"说起来家族"：
- "说起来不好意思，读《围城》之前……"
- "说起来有点丢人，我是在搬家收拾旧书的时候……"
- "说起来有点不好意思，这本书放在我书架上有三年多了……"

同一个骨架，换几个词就当作不同风格——这是隐蔽的 AI 偷懒，读三篇就会暴露。

**2026-07-17 用户纠正**：之前用 8 种编号模式轮流选，本质还是有限池子里挑，世界上一百种以上的开头方式不该被编号限死。**正解不是从目录里选编号，是结构分析。** 废旧模式库，换结构分析规则。

**核心原则**：每个开头必须从这本书的**唯一特征**自然生长出来，不是套骨架填空。

**可执行规则**：

1. **采集**：写出开头第一段（前 2-3 句，不要超过 80 字）
2. **结构分析**：用这个公式检查开头的结构 DNA：
   - **起始词性**：第一句以什么开头？（时间名词/人称代词/疑问词/连词/副词/动词/数量词/方位词/关联词——写出具体是什么）
   - **句式骨架**：主谓宾结构还是状主谓？是判断句还是陈述句还是疑问句？
   - **信息引入方式**：第一句是引入物、引入事、引入人还是引入感受？
3. **对比最近 3 篇**：把新开头的结构 DNA 与最近 3 篇逐一比对。**三个维度中任意两个一致 → 与那篇结构重复 → 重写开头**
4. **绑死这本书**：把开头第一句中的书名词、人物名、情节替换成任何其他书。如果替换后句子仍然成立 → 开头是通用模板，绑死这本书 → 重写

**铁律**：
- ❌ 禁止"我一直以为……直到……"句式（已用 3 次，疲劳）
- ❌ 禁止"有没有过这种X——……？"句式（已用 2 次，疲劳）
- ❌ 禁止"说起来/说实话/说来惭愧/说XX"打头（历史问题）
- ✅ 开头必须引用书中一个**具体细节**（一句话/一个情节/一个画面/一个物品/一个人物），不是书评式概论
- ✅ 写完自查时换任何书替换测试：如果开头句把书名换了还成立，重写

### §R.2.2 读书笔记结构（来自真实文章的反推）

**字数**：
- **汉字 ≥ 3,000**（2026-07-24 用户纠正：用 `len(re.findall(r'[一-鿿豈-﫿]', text))` 计数，禁止用 `len(str)`）
- 发布后简书显示"字数:2837"——这个数是总字符数（含标点英文），**不是汉字数**。差异来自标点、数字、英文、Markdown 语法的字符也被计入平台字数，但汉字计数铁律要求汉字 ≥ 3,000。
- **写作时以汉字数为准，不对齐 content.length**。汉字达标后平台字数自然 ≥ 3,000。
- 发布前从已发布的文章页面读取平台字数确认。若不足 3,000，从「编辑已发布文章」入口进入后，在末尾追加段落补足汉字数（不得覆盖正文）。

**段落节奏（手机端适配，v1.31 统一为 30 字标准）**：
- 平均段长 **30 字左右**，最长不超过 60 字
- 段落长度**长短交替**，最短一段1句话（10字），最长一段3句话
- 允许极短段落：一个词一段都行，制造阅读节奏
- 段与段之间必须空行
- 一段只说一个意思，说完就换，不用过渡句

> 🔍 **注**：高赞头部文章平均段长 63-66 字，但实操表明 30 字段长在手机端阅读节奏更好。写作时以 30 字为准。

**读书笔记结构**（来自真实文章的反推）：

```
[开头·个人引入]
不用"说起来/说实话/说来惭愧"打头。
选一个不同的开头骨架（见 §R.2.1 结构分析规则）。
不用写作者简介、出版年份、豆瓣评分

[主体·挑 1-3 个触动点]
每点写法：
"书里……（一句概括）"
"读到这我愣了一下——……"
不用"说实话""说实话""让我想起"做连接词
自然过渡，说完一个点空行换下一个

[结尾·收束]
不总结全书。
一句感受收住，或者引用书里最扎自己的那句话。
说完就停。

**配图规则（实测三篇头部文章）**：

| 文章 | 字数 | 配图数 | 图字比 | 图片位置 |
|------|------|--------|--------|---------|
| 读书是为自己受用（977赞） | 1,126 | 1 | ~1,100字/图 | 结尾附近 |
| 会读书和不会读书的人（645赞） | 1,974 | 5 | ~400字/图 | 均匀分布在段落间 |
| 好读书不好读书（657赞） | 626 | 1 | ~600字/图 | 开头之后 |

**规律**：

### §R.2.3 质量门控铁律 — 全文零AI味（2026-07-11 新增）

> **核心原则**：每篇文章写完到发布前，必须按以下 8 条逐项自检。**任何一项不通过即重写该部分，宁可不发。** 每日一篇的节奏让位于质量。

1. **✅ 全文零 AI 味**：用"陌生人读一遍会不会觉得这是AI写的"这个标尺自检。AI味的典型症状：①全篇没有一个具体的数字/时间/地点 ②每个观点都正确但不过心 ③句子太完整、没有口语的破碎感 ④情绪都是"感动/震撼/深思"这类通用词。如果任何一段读出AI味 → 整段重写，加上只有你才知道的细节。
2. **✅ 深度足够**：不是复述书的内容，是"这本书让我改变了什么"。每个触动点必须有自己的解读，不能停留在"书里写了X，我觉得对"的层面。范例：《围城》——"方鸿渐不是渣，他是没有勇气面对真实，所以一辈子打烂牌。我辞职前跟他一样——明知道现在的工作是死路，就是不敢掀桌子。"
3. **✅ 细节具体**：每个观点必须附着在具体细节上——书中的一句话、一段情节、一个画面。没有细节支撑的感受是空洞的套话。如果去掉书名一样能套在任何书上 → 不合格。
4. **✅ 真诚不做作**：检查全文是否有任何一句像"金句""总结语""人生道理"——就是那种单独拿出来可以被摘抄的话。如果有，删掉或改写成平淡的语气。简书读者最敏锐的就是"这句话是写出来给人看的"vs"这句话就是我心里想的"。
5. **✅ 个人故事真实**：个人经历部分必须有可验证的细节（时间、地点、对话、具体数字），不能写"我有一个朋友"。如果暂时没有合适的个人故事，宁可不写也别编。阅读量证明：有真实细节的个人故事（《平凡的世界》"辞职后阳台发呆"）点赞 22；空洞的私人感受点赞低。
6. **✅ 避免 AI 套话**：全篇检查以下标记：①"给我上了一课" ②"突然明白了" ③"正如书中所说" ④"让我意识到" ⑤"这就是XX的力量" ⑥任何"大词"（命运/生命/人性/灵魂）。如果有，全部改为具体描述（例："让我意识到"→ "那天晚上我坐在阳台抽了三根烟"）。
7. **✅ 开头不可替代**（与 §R.2.1 第 4 步合并）→ 写作时检查即可，不单独重复
8. **✅ 结尾不说教**：最后一段如果包含"如果你也……""希望我们都能……""愿你……"类句式 → 重写。结尾只需要一个画面/一句感受/一个具体动作，说完就走。

> ⚠️ **质量 > 频率**：任何一项自检不通过，今天不发布。用户明确要求"质量必须高"和"零AI味"，这是不可妥协的红线。

### §R.2.4 结尾多样化规则（v1.24 重写）

**发现问题**：《百年孤独》结尾"也可能，什么都没有。那更让人害怕。"——《三体》结尾也是"也可能，什么都没有。那更让人害怕。"同一种句式反复用，换几个词就当作不同结尾。

**2026-07-17 用户纠正**：与开头模式库同样的问题——有限模式池轮换不是多样性。**废旧模式库，换结构分析规则。**

**核心原则**：结尾不是总结。每个结尾只能做一件事：一句感受、一个画面、一个动作、一句书名引用。

**可执行规则**：

1. **结构分析**：写出最后一段（1-2 句），分析其结构 DNA：
   - **收束方式**：以句号结尾的陈述？以空格/省略号结尾的留白？以引号结尾的引用？
   - **结束动作**：是写"我做了什么"（行动型）还是"我想了什么"（感受型）还是"书里说了什么"（引用型）？
   - **节奏感**：倒数第二句是短句还是长句？有没有刻意用短句制造停顿？
2. **对比最近 3 篇的结尾**：三个维度中任意两个一致 → 重写结尾
3. **不可替换测试**：把结尾中具体的书名/人名/情节词换掉。如果句子仍然成立 → 结尾是通用套话，重写

**铁律**：
- ❌ 禁止"愿/希望/如果你也"类升华句式
- ❌ 禁止结尾突然总结全书
- ❌ 禁止"这就是XX的力量/意义"句式
- ✅ 结尾只说一具体事，说完就停

### §R.3 标题规范

**标题限制**：2-30 字，超出会被平台拦截。

**禁止格式**：以下格式表明在偷懒，禁止使用。
- ❌ "读《XXX》"
- ❌ "《XXX》读后感"
- ❌ "关于XXX的一些想法"

**好标题标准**：必须有钩子，让人想点进来。
- ✅ 包含个人结果/变化："读完XXX，我XXX了"
- ✅ 包含具体痛点/解决方案："如果你也XXX，读读XXX"

> 标杆范例：`"她十七岁才第一次走进教室"`（《你当像鸟飞往你的山》）——没有书名号，只陈述一个具体反常事实，钩子拉满。拟新标题时以这个为标准。

### Step 5: 填写正文（支持两种编辑器模式）

> ⚠️ **最新验证（v1.5）**：新文章默认使用 **Rich Text 模式**（`div.kalamu-area`），而非 Source 模式（textarea）。已有文章保持各自创建时的模式。每次执行需先检测编辑器模式再选择写入方式。

编辑器有两个模式：

| 模式 | 选择器 | 读写方式 |
|------|--------|---------|
| Source（Markdown） | `textarea#arthur-editor._3swFR.source` | `editor.value = markdown内容` + dispatchEvent(input) |
| Rich Text | `div.kalamu-area[contenteditable="true"]` | `editor.innerHTML = html内容` + dispatchEvent(input) |

**检测编辑器模式后使用对应写入方式（v1.5 已验证两种模式）：**

```javascript
browser_evaluate(function=() => {
  let editor, isSourceMode;
  
  // 1. 检测编辑器模式
  const textarea = document.querySelector('textarea#arthur-editor');
  const kalamu = document.querySelector('div.kalamu-area');
  
  if (textarea && textarea.offsetParent !== null) {
    // Source 模式
    editor = textarea;
    isSourceMode = true;
  } else if (kalamu && kalamu.offsetParent !== null) {
    // Rich Text 模式（新文章默认）
    editor = kalamu;
    isSourceMode = false;
  } else {
    throw new Error('编辑器未找到');
  }
  
  if (isSourceMode) {
    // Markdown 写入
    editor.value = `## 小标题

这是正文段落。

自然结尾，不用总结。`;
  } else {
    // HTML 写入（段落间用空<p></p>）
    editor.innerHTML = `<p>第一段。</p><p></p><p>第二段。</p>`;
  }
  
  editor.dispatchEvent(new Event('input', { bubbles: true }));
})
```

**🔴 铁律——正文写入方式（2026-07-17 新增，因违反导致文章被锁）**：
- **禁止**使用 base64/DataURL/文件读取/`fetch`/`XMLHttpRequest` 等任何间接方式注入内容
- **禁止**将内容写到文件再读入
- **唯一允许方式**：把全文作为 JS 字符串字面量直接赋值给 `editor.value`，嵌入在 `browser_evaluate` 的 function 参数中
- 正文字符串中的换行用 `\n` 转义，单引号用 `\'` 转义，反斜杠用 `\\` 转义
- 使用 `Node.js` 脚本自动生成转义后的 evaluate 函数代码

**🔴 2026-07-18 实践补充**：当内容较长（>3,000 字符含中文）时，browser_evaluate 中 `e.value = '内容'` 易因换行符报 SyntaxError。**替代方案**：使用 `browser_run_code_unsafe` 配合 page.evaluate：

```javascript
// browser_run_code_unsafe（内容在 backtick 中自然支持换行）
async (page) => {
  const content = `全文内容直接写在这里，
    换行也没关系，backtick 支持。`;
  return await page.evaluate((c) => {
    document.querySelector('textarea#arthur-editor').value = c;
    // dispatchEvent ...
  }, content);
}
```

**关键区别**：`browser_run_code_unsafe` 的 code 参数使用 backtick 模板字面量，内容中的换行符在 JS 中合法；而 `browser_evaluate` 的 function 参数被序列化为 JSON 字符串，换行符会破坏语法。

**格式要求**：
- 段落之间留空行
- 代码用代码块包裹
- 标题用 `##` 三级以内
- 引用用 `>` 符号

## §2.1 Source 模式图片插入（先写文→光标定位→逐张上传）

> 🔴 **2026-07-15 修正**：之前方案是"先批量上传图片提取 URL → 一次性写入完整 Markdown"，但这导致图片位置难以精确控制（要先算字符位置再拼接 URL，容易出错）。**正解是**：写好完整正文 → setSelectionRange 定位光标 → 逐张上传插入。

**流程图**：

```
写完整正文 → 确定每张图的段落位置 → 光标定位到该段末尾
  → 调出图片对话框 → 上传图片（![](url) 自动插入光标处）
  → 光标移下一图位置 → 上传第二张 → 第三张 → 发布更新
```

**无需手动拼接 URL，无需提取 CDN URL，无需分段构建文字。**

**操作代码**（Source 模式，编辑器是 textarea）：
```javascript
// 1. 先把光标定到目标段落后
browser_evaluate(function=() => {
  const editor = document.querySelector('textarea#arthur-editor');
  const text = editor.value;
  // 按 \n\n 切分段落
  const paras = text.split('\n\n');
  // 定位到第 N 段末尾（示例：第 12 段后，即 25% 位置）
  let cursorPos = 0;
  for (let i = 0; i <= 12 && i < paras.length; i++) {
    cursorPos += paras[i].length + 2; // +2 for "\n\n"
  }
  editor.setSelectionRange(cursorPos, cursorPos);
  editor.focus();
})

// 2. 打开图片对话框
browser_evaluate(function=() => {
  document.querySelector('a[data-action="openImageModal"]')?.click();
})

// 3. 点击上传按钮
browser_click(target='text=点击上传（可多张）')

// 4. 上传文件（图片在 C:\Users\59314\claudework\ 下）
browser_file_upload(paths=['C:\\Users\\59314\\claudework\\jianshu_img.jpg'])

// 上传完成后 dialog 自动关闭，![](url) 已插入光标位置
// 重复 1-4 把剩下2张图插入剩余位置
```

**三步走完 3 张图**（示例定位到第 12/22/34 段后）：

> ⚠️ **光标偏移警告**：每插入一张图片后 textarea 内容长度增加 ~149 字符。**每次 setSelectionRange 必须基于当前 editor.value.split('\n\n') 实时计算**，禁止使用预先计算的固定位置值。下面示例中每步独立计算段落位置，是对的。

```javascript
// 第1张：定位到段落12末尾（25%位置）
browser_evaluate(function=() => {
  const editor = document.querySelector('textarea#arthur-editor');
  const paras = editor.value.split('\n\n');
  let pos = 0;
  for (let i = 0; i <= 12; i++) pos += paras[i].length + 2;
  editor.setSelectionRange(pos, pos); editor.focus();
})
// 打开对话框→上传→自动插入
browser_evaluate(function=() => document.querySelector('a[data-action="openImageModal"]')?.click())
browser_click(target='text=点击上传（可多张）')
browser_file_upload(paths=['C:\\Users\\59314\\claudework\\jianshu_img1.jpg'])

// 第2张：定位到段落22末尾（50%位置）
browser_evaluate(function=() => {
  const editor = document.querySelector('textarea#arthur-editor');
  const paras = editor.value.split('\n\n');
  let pos = 0;
  for (let i = 0; i <= 22; i++) pos += paras[i].length + 2;
  editor.setSelectionRange(pos, pos); editor.focus();
})
browser_evaluate(function=() => document.querySelector('a[data-action="openImageModal"]')?.click())
browser_click(target='text=点击上传（可多张）')
browser_file_upload(paths=['C:\\Users\\59314\\claudework\\jianshu_img2.jpg'])

// 第3张：定位到段落34末尾（75%位置） → 同上模式
```

**🔴 第 4 步 — 清空 alt 文本（2026-07-16 新增）**

Source 模式上传后，简书自动把文件名填入 `[]`：`![jianshu_img1.jpg](url)`。必须清空为 `![]`，否则读者看到文件名。

```javascript
browser_evaluate(function=() => {
  const editor = document.querySelector('textarea#arthur-editor');
  editor.value = editor.value.replace(/!\[\w+\.\w{3,4}\]/g, '![]');
  editor.dispatchEvent(new Event('input', { bubbles: true }));
  return 'alt texts cleaned';
})
```

**图片 URL 格式说明**：
- Source 模式上传后自动生成格式为 `![filename](url)`（以文件名作为 alt 文本）
- 写入时用 `![](url)`（空 alt 文本）同样完全兼容，两者在渲染上无差异
- 参考坑 #26：拼接格式必须严格无空格 `'![](' + url + ')'`

## §7 投稿注意事项

### 「读书」专题投稿要求
- 文章须与读书相关，鼓励个人阅读感悟
- 无推广信息（外链、二维码、公众号等）
- 配图不能带水印
- 原创
- 不能直接抄袭原文来投稿
- 注意排版美观、内容结构完整

### 投稿策略
- 每天投稿不超过 5 次，避免密集投稿触发限制
- 首投「读书」专题，这是简书最大流量池（5.5M关注者）
- 🔴 **投稿窗口仅发布时可用**：发布后"推荐专题"面板是唯一的投稿入口，发布后立即操作，不得先导航离开
- 投稿后需要等待专题编辑审核，非即时生效
